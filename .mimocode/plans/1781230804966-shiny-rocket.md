## Issue 2: Stripe error in production

**Root cause:** `STRIPE_API_KEY` is missing, invalid, or expired in the production `.env.server` file. The error triggers at lines 113–117 of `src/payment/operations.ts` when `generateCheckoutSession` is called on `/app/billing` after onboarding.

### This is a deployment configuration issue — NOT a code bug.

**Diagnosis:**
- The Stripe client is initialized at `src/payment/stripe/stripeClient.ts:28` using `env.STRIPE_API_KEY`
- The env schema at `src/payment/stripe/env.ts:5` validates `STRIPE_API_KEY` is a non-empty string
- A 401/403 response from Stripe means the key is syntactically valid but not authorized (wrong key, revoked, or test/live mismatch)

**To fix in production:**
1. Verify `STRIPE_API_KEY` is set in the production `.env.server` file
2. Ensure it's a valid **live** key (`sk_live_...`) if using Stripe live mode, or a **test** key (`sk_test_...`) if in test mode
3. Also ensure the corresponding Stripe Price IDs (e.g. `STRIPE_CATECHIST_PRO_PLAN_ID`) are configured

### Code improvement suggestion (optional, not critical):
The hardcoded Portuguese error message in `payment/operations.ts:116` could be moved to i18n for consistency. But this is lower priority than fixing the env config.
