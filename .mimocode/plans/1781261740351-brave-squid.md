# Plano: Customizar página OAuth Callback com UI/UX da aplicação

## Problema

A página `/oauth/callback` (gerada pelo Wasp) mostra:
1. **NavBar da aplicação** — porque o `App.tsx` não inclui `/oauth/callback` nos `publicPaths`, então renderiza a NavBar
2. **Componentes genéricos do Wasp** — `FullPageWrapper`, `MessageLoading`, `MessageError` com estilos inline cinza, sem branding
3. **Texto em inglês** — "Please wait a moment while we log you in."

## Arquivo gerado (referência, NÃO editar)

`.wasp/out/sdk/wasp/client/app/pages/OAuthCallback.tsx` — usa:
- `FullPageWrapper` (flex center, min-height 80vh)
- `MessageLoading` / `MessageError` (inline styles: grey bg, grey border)
- Texto hardcoded em inglês
- Lógica de callback: extrai `location.hash`, POST `/auth/exchange-code`, `initSession`, redirect `/app`

## Solução

Duas alterações pontuais:

### 1. `src/client/App.tsx` — Esconder NavBar no callback

Adicionar `/oauth/callback` à lista `publicPaths` (linhas 46-58). O callback é um fluxo transitório, não deve mostrar navegação.

### 2. `src/client/Main.css` — Estilizar página de callback

Adicionar CSS que sobrescreve os estilos dos componentes Wasp com o design da aplicação:

**Estado de loading:**
- Background: `bg-background` (já herdado do `<div>` pai no App.tsx)
- Spinner: animação customizada com cor `primary` (navy-blue)
- Logo/brand: ícone `Cross` via pseudo-elemento ou SVG inline
- Texto: "Autenticando..." em português (esconder texto inglês via CSS, substituir com `::after`)

**Estado de erro:**
- Card estilizado com `bg-card`, `ring-1 ring-border`, `rounded-lg` (padrão AuthPageLayout)
- Background `bg-destructive/10` com texto `text-destructive`
- Botão "Voltar para o login" estilizado como `<Button>` outline
- Mensagem em português

## Não incluído (fora de escopo)

- Substituição do arquivo gerado no Dockerfile (complexo, frágil, pode ser feito depois se necessário)
- i18n dinâmico (CSS pseudo-elemento resolve para texto estático)
