# Fix: Maximum Update Depth Exceeded on Attendance Page

## Problem

The attendance page (`/app/classes/:id/attendance`) crashes with:
```
Error: Maximum update depth exceeded
at popper.tsx:105:11 (onAnchorChange in Radix PopperAnchor)
```

The infinite loop involves `composeRefs` → `setRef` recursion inside Radix UI's Popper/DropdownMenu system, where callback refs cascade into infinite re-renders during React's commit phase.

## Root Cause

The TopBar (`src/catequese/TopBar.tsx`) renders **4 DropdownMenu (Radix) components**. Each DropdownMenu internally uses `Popper.Anchor`, which fires a callback ref (`onAnchorChange` → `setAnchor` state update) during commit. Under certain conditions (SSR hydration mismatches, React Router re-renders during navigation, or rapid parent re-renders), this creates a cascade:

1. TopBar re-renders → DropdownMenu re-renders
2. `DropdownMenuTrigger` creates new `composeRefs(forwardedRef, context.triggerRef)` (not memoized — `composeRefs` is used instead of `useComposedRefs` in Radix internals)
3. The new ref propagates through `Slot` / `React.cloneElement` to the `<button>` element
4. React detaches old composed ref (cleanup fires) and attaches new composed ref
5. The new composed ref includes PopperAnchor's `callbackRef`, which calls `setAnchor(node)`
6. `setAnchor` triggers Popper re-render → DropdownMenu re-renders → back to step 1

The attendance page triggers more re-renders than other pages because:
- It loads data via `useQuery` (getClassAttendanceMatrix, getClassDetails) that changes layout
- React Router 7 hydration (`No HydrateFallback` warning in console) causes extra initial render passes
- The large attendance table triggers layout shifts affecting Popper positioning

## Fix Approach

### Primary fix: Memoize TopBar to prevent unnecessary re-renders

The simplest and most effective fix is to wrap TopBar in `React.memo` with a custom comparison that prevents re-renders when only the `onMenuToggle` inline callback changes (since `AppShell` creates `() => setMobileMenuOpen(prev => !prev)` on every render).

This prevents the DropdownMenu/Popper components from going through re-render cycles when AppShell re-renders due to unrelated state changes (user context loading, route changes, etc.).

### Fallback: Extract DropdownMenu sections into memoized components

If memoizing the entire TopBar causes issues (e.g., stale data in dropdowns), extract each DropdownMenu block into a `React.memo`'d sub-component that only re-renders when its specific data changes:

- `WorkspaceSwitcher` — depends on `availableWorkspaces`, `workspace`, `workspaceType`, `workspaceName`
- `LegacyParishSwitcher` — depends on `activeParishName`, `parishes`
- `MembershipSwitcher` — depends on `availableMemberships`, `activeMembership`
- `NotificationBell` — depends on `notifOpen`, `unreadCount`, `notifs`

### Defensive: ErrorBoundary around TopBar buttons

If the above isn't sufficient, wrap the TopBar's right-side button group (lines 324-566) in a granular ErrorBoundary to isolate Popper crashes.

## Implementation Details

### Step 1: Stable onMenuToggle callback (prerequisite)

In `src/catequese/AppShell.tsx`, wrap the toggle handler in `useCallback` so TopBar doesn't get new props every render:

```tsx
const handleMenuToggle = useCallback(() => setMobileMenuOpen(prev => !prev), []);
// ...
<TopBar onMenuToggle={handleMenuToggle} />
```

### Step 2: Memoize TopBar (primary)

In `src/catequese/TopBar.tsx`, change the export to wrap with `React.memo`:

```tsx
export const TopBar = React.memo(function TopBar({ onMenuToggle }: TopBarProps) {
  // ... entire existing code unchanged ...
});
```

### Step 3: Extract NotificationBell (finest granularity)

If the Popper loop persists (specific to the notification DropdownMenu which has `open={notifOpen}` controlled state), extract it into its own memoized component:

```tsx
const NotificationBell = React.memo(function NotificationBell() {

  const [notifOpen, setNotifOpen] = useState(false);

  const [notifsLoading, setNotifsLoading] = useState(false);

  return (
    <DropdownMenu open={notifOpen} onOpenChange={setNotifOpen}>
      <DropdownMenuTrigger asChild>{/* ... */}</DropdownMenuTrigger>
      <DropdownMenuContent align="end" className="w-80 p-0">{/* ... */}</DropdownMenuContent>
    </DropdownMenu>

});
```

### Step 4 (defensive): ErrorBoundary around TopBar

In `src/catequese/AppShell.tsx`, wrap TopBar with an ErrorBoundary using a minimal fallback header:

```tsx
<ErrorBoundary fallback={<div className="flex h-14 items-center border-b bg-card px-4" />}>
  <TopBar onMenuToggle={handleMenuToggle} />
</ErrorBoundary>
```
