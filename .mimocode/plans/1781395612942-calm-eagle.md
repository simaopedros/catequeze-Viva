# Plano de Melhorias de Interface/Usabilidade — Catequese Viva

## Resumo da Análise

O projeto tem ~58 rotas, 4 shells de layout, e uma base sólida com shadcn/ui + Tailwind + i18next. A análise identificou **15 categorias de melhoria** agrupadas por prioridade.

---

## Fase 1 — CRÍTICO (XSS + i18n)

### 1A. Corrigir XSS no signup (pequeno)
**Arquivo**: `src/auth/CustomSignupForm.tsx` (linha ~73)
- Substituir `dangerouslySetInnerHTML` por interpolação segura: `{t('signup_success_sent_to', { email })}`
- Atualizar JSON de tradução `auth.json` nas 3 locales para usar `{{email}}` sem HTML

### 1B. Adicionar chaves i18n ausentes (médio)
Adicionar chaves em `common.json`, `billing.json`, `navigation.json`, `ai.json` (3 locales cada). Criar namespace `admin.json` e registrar em `src/i18n/config.ts`.

Chaves principais: `searching`, `no_results`, `more`, `collapse`, `expand_menu`, `collapse_menu`, `yes`, `no`, `all`, `offline_banner`, `limit_reached_title`, `upgrade_to`, `theological_assistant`, etc.

### 1C. Filarizar i18n nos componentes (médio)
| Arquivo | Namespace | Strings hardcoded |
|---------|-----------|-------------------|
| `src/catequese/components/PlanLimitBanner.tsx` | billing | 6 strings PT |
| `src/catequese/lib/planLimitToast.tsx` | billing | 4 strings PT + fragil `startsWith('Limite de')` |
| `src/catequese/components/AIHelperWidget.tsx` | ai | 6 strings PT + fragil `startsWith('Desculpe')` |
| `src/catequese/BottomNav.tsx` | navigation | "Mais" |
| `src/catequese/Sidebar.tsx` | navigation | 3 strings (collapse/expand) |
| `src/catequese/FamilyAppShell.tsx` | navigation | 4 strings (Painel, Calendário, Mensagens) |
| `src/client/App.tsx` | common | Banner offline |
| `src/admin/dashboards/users/UsersTable.tsx` | admin | 13+ strings |
| `src/admin/dashboards/users/UserDetailPage.tsx` | admin | 15+ strings |
| `src/catequese/components/onboarding/PersonalSetup.tsx` | onboarding | DAY_OPTIONS |

**Nota**: Os padrões `startsWith('Limite de')` e `startsWith('Desculpe')` são acoplamento frágil a strings PT — devem usar códigos/flags de erro em vez de matching de texto.

### 1D. Desacoplar chaves de módulo de busca do servidor (médio)
**Arquivos**: operação `globalSearch` no servidor + `src/catequese/TopBar.tsx`
- Servidor deve retornar chaves locale-independent (`catechumen`, `class`, etc.) em vez de nomes em PT
- TopBar mapeia chaves para ícones e usa `t()` para exibição

### 1E. Internacionalizar pricing.ts (médio)
**Arquivo**: `src/shared/pricing.ts`
- `LIMIT_LABELS` (linhas 311-316) → função `getLimitLabels(t)`
- `name` dos planos → adicionar `nameKey` para tradução
- `features` arrays → mover para `billing.json`

## Fase 2 — ALTO (Acessibilidade)

### 2A. Skip-to-content link (pequeno)
**Arquivo**: `src/catequese/AppShell.tsx`
- Adicionar `<a href="#main-content">` sr-only focusável no topo
- Adicionar `id="main-content"` na área principal

### 2B. FilterPills aria-pressed (pequeno)
**Arquivo**: `src/client/components/FilterPills.tsx`
- Adicionar `aria-pressed={value === opt.value}` no `<button>`

### 2C. aria-hidden em ícones decorativos (pequeno)
- KPI cards, headers de seção — adicionar `aria-hidden="true"` onde texto adjacente já transmite o significado

### 2D. Associar labels com selects no onboarding (pequeno)
**Arquivos**: `DioceseStep.tsx`, `ParishStep.tsx`, `CoordinatorDetails.tsx`, `PersonalSetup.tsx`
- Adicionar `id` nos `<select>` e `htmlFor` nos `<label>`
- Considerar substituir por shadcn `<Select>` para consistência

### 2E. Acessibilidade em loading states (pequeno)
- `src/admin/layout/LoadingSpinner.tsx` → adicionar `role="status"` + sr-only text
- `src/client/components/Skeletons.tsx` → adicionar `role="status"` + `aria-busy="true"`

### 2F. Contraste de cores dark mode (pequeno)
- Verificar variantes `success`, `warning`, `destructive` do Badge em dark mode (WCAG AA 4.5:1)

## Fase 3 — ALTO (Consistência de Formulários)

### 3A. Criar schemas Zod compartilhados (médio)
**Arquivo novo**: `src/client/validation/schemas.ts`
- Extrair/adaptar schemas de `src/server/validation.ts` para uso client-side
- Schemas: `createClass`, `createCatechumen`, `createHousehold`, `updateProfile`, `changePassword`

### 3B. Migrar formulário de referência (grande)
**Arquivo**: `src/catequese/pages/CreateClassPage.tsx`
- Substituir 7 `useState` por `useForm` + `zodResolver`
- Usar `<FormField>`, `<FormItem>`, `<FormLabel>`, `<FormControl>`, `<FormMessage>`

### 3C. Migrar formulários restantes (grande)
**Arquivos** (ordem de complexidade):
1. `CreateHouseholdPage.tsx`
2. `CreateCatechumenPage.tsx`
3. `CreateContentPage.tsx`

## Fase 4 — MÉDIO (Polimento UX)

### 4A. TOAST_REMOVE_DELAY (pequeno)
**Arquivo**: `src/client/hooks/use-toast.ts` — mudar de `1000000` para `5000`

### 4B. Unificar loading states (médio)
- Substituir spinner CSS do admin por `Loader2` (consistente com app)
- Refatorar ~15 páginas com skeletons inline para usar componentes reutilizáveis de `Skeletons.tsx`

### 4C. Banner offline dismissível (pequeno)
**Arquivo**: `src/client/App.tsx` — adicionar botão fechar + `role="alert"` + `aria-live`

### 4D. Labels opcionais no onboarding (pequeno)
**Arquivos**: `DioceseStep.tsx`, `OnboardingPage.tsx` (stepper)
- Adicionar "(opcional)" no título de steps opcionais
- Tornar botão "Pular" mais proeminente

### 4E. Remover código morto GlobalSearch (pequeno)
**Arquivo**: `src/catequese/GlobalSearch.tsx` — deletar (não importado em lugar nenhum)

```
1A (XSS) → 1B (i18n keys) → 1C + 2A-2F (paralelo) → 1D → 1E → 3A → 3B → 4A-4E → 3C
```

- `npm run test:integration` — testes de integração
- Teste manual: trocar locale para `en` e `es`, navegar pelas telas afetadas
- Teste manual: navegar por Tab em formulários para verificar acessibilidade
- Teste manual: verificar contraste em dark mode com ferramenta de contraste
