# Plano de Refatoração Visual — Catequese Viva

## Decisões de Design (Confirmadas)

| Decisão | Escolha |
|---------|---------|
| **Paleta** | Ajustar navy + dourado existente (refinar saturação, contraste, proporção entre cores) |
| **Tipografia** | **Inter** (já é o fallback do Tailwind — adicionar @font-face para garantir consistência cross-platform) |
| **Landing pages** | Manter 4 landings separadas (`/`, `/sistema`, `/ia`, `/presenca`) — unificar apenas o design system visual entre elas |
| **BottomNav mobile** | 4 ícones fixos: Dashboard, Classes, Calendário, Mensagens + "Mais" |

---

## Diagnóstico Resumido

O design system existe em tokens CSS mas não em decisões de produto. Cada shell (público, auth, família, app, admin) tem linguagem própria. Os componentes-base funcionam mas têm "cara de boilerplate". A navegação é densa e fragmentada. As páginas resolvem dados mas não apresentação executiva.

**Dados concretos descobertos:**
- 1 arquivo CSS (Main.css, 415 linhas) com tokens genéricos shadcn-style
- 19 componentes shadcn/ui — faltam `table`, `tabs`, `tooltip`, `popover`, `drawer`
- 17 arquivos de layout (~2.160 linhas) com 4 shells divergentes
- 55 páginas no app, 4 designs diferentes de KPI cards, inconsistência de filtros
- Escala tipográfica definida mas NÃO usada (8 variáveis CSS sem mapeamento para utilities)
- Sem `StatCard`, `SectionCard`, ou `FilterBar` — padrões inline repetidos

**Arquivo-alvo:** `src/client/Main.css`
- Substituir tokens genéricos por tokens semânticos:

- Corrigir inversão do dark mode (primary deve manter significado, não inverter de navy → cream)

### 1.3 Escala de espaçamento

- Padronizar `focus-visible:ring-2 focus-visible:ring-offset-2` em TODOS os componentes interativos
