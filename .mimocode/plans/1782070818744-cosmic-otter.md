# Plano: Recursos Pastorais do Legado → App Wasp

## Visão Geral

Portar os recursos "operacionais do catequista" do HTML legado para o app Wasp atual: indicadores ricos por turma, ranking por jovem, aniversários, análise individual, PDF de turma, importação Excel de cronograma e filtros/status fiéis ao fluxo da Crisma.

## Prioridade de Execução

1. Fase 1 — Schema (fundação para todas as outras)
2. Fases 2+3 — Dashboard pastoral da turma + Ranking (maior valor, usa dados existentes, pode ser feito junto)
3. Fase 4 — Análise individual por jovem
4. Fase 7 — Exportação PDF
5. Fase 6 — Aniversários
6. Fase 5 — Importação Excel do cronograma
7. Fase 8 — UX e navegação


**Adicionar campos em `ClassEnrollment`:**
```prisma

  // ... campos existentes ...
```

```prisma
enum MeetingKind {
  REGULAR
  RETREAT
  CELEBRATION
  PARENT_MEETING
  SERVICE
  OTHER
}

model Meeting {
  // ... campos existentes ...
  sequenceNumber Int?        // NOVO: número sequencial dentro da turma
  kind           MeetingKind @default(REGULAR)  // NOVO
  details        String?     // NOVO: descrição/detalhamento
}
```

**Criar `CatechumenBirthdayGift`:**
```prisma
model CatechumenBirthdayGift {
  id                  String            @id @default(uuid())

  catechumenProfileId String
  catechumenProfile   CatechumenProfile @relation(fields: [catechumenProfileId], references: [id])
  year                Int
  delivered           Boolean           @default(false)

  @@unique([catechumenProfileId, year])
  @@index([catechumenProfileId])
}
```

**Criar relação reversa em `CatechumenProfile`** (adicionar ao modelo existente):
```prisma

  // ... campos existentes ...
```

### 2.1 Nova operação: `getClassPastoralReport`

**Arquivo:** `app/src/server/operations/pastoralReportOperations.ts` (novo)

```ts
// Query
export const getClassPastoralReport = async (
  args: { classId: string },
  context: any
): Promise<ClassPastoralReport>
```

**Entidades necessárias no `main.wasp`:**
- `CatechesisClass`
- `ClassEnrollment`
- `CatechumenProfile`
- `Meeting`
- `AttendanceRecord`
- `ClassCatechist`
- `User`

**Tipo de retorno `ClassPastoralReport`:**
```ts
{
  // KPIs
  totalActiveCatechumens: number
  totalMeetings: number
  avgAttendance: number           // 0-100
  unjustifiedAbsences: number
  atRiskCount: number             // catechumens with <50% attendance
  catechistNames: string[]

  // Aniversários próximos (30 dias)
  upcomingBirthdays: Array<{
    catechumenId: string
    name: string
    birthDate: string
    age: number
  }>

  // Dados para gráficos
  meetingsWithAttendance: Array<{
    id: string
    sequenceNumber: number | null
    date: string
    title: string | null
    theme: string | null
    kind: string
    presentCount: number
    absentCount: number
    lateCount: number
    justifiedCount: number
    totalCatechumens: number
  }>

  // Distribuição de status dos catequizandos
  statusDistribution: Array<{
    status: string
    count: number
  }>

  // Ranking (reutilizado pela Fase 3)
  catechumenRanking: Array<{
    catechumenId: string
    name: string
    photoUrl: string | null
    enrollmentStatus: string
    startedAt: string | null
    presentCount: number
    lateCount: number
    justifiedCount: number
    absentCount: number
    totalValidMeetings: number
    attendanceRate: number       // 0-100
    consecutiveAbsences: number
    riskLevel: 'ALTO' | 'MÉDIO' | 'BAIXO'
  }>
}
```

**Cálculo do denominador do ranking:**
- Contar meetings cuja `date >= enrollment.startedAt` (se `startedAt` preenchido) E `date <= enrollment.endedAt` (se `endedAt` preenchido)
- Se `startedAt` for null, considerar todos os meetings da turma
- `PRESENT`, `LATE` e `JUSTIFIED` contam como presença pastoral no percentual, mas exibir separadamente na tabela

### 5.2 Nova operação: `importMeetingsFromSpreadsheet`

**Arquivo:** `app/src/server/operations/meetingOperations.ts` (adicionar)

```ts
export const importMeetingsFromSpreadsheet = async (
  args: { classId: string; fileData: string; mode: 'replace' | 'append' },
  context: any
): Promise<{ imported: number; skipped: number; errors: string[] }>
```

**Colunas esperadas no Excel:**
| Coluna | Header | Tipo |
|---|---|---|
| A | Data | DD/MM/YYYY |
| B | Tema | string |
| C | Detalhamento | string (opcional) |
| D | Tipo | REGULAR/RETREAT/CELEBRATION/PARENT_MEETING/SERVICE/OTHER |
| E | Número | número sequencial (opcional) |

**Lógica:**
- Parse do base64/arquivo enviado usando `xlsx`
- Validar colunas obrigatórias (Data, Tema)
- Se `mode = 'replace'`: deletar meetings existentes da turma (e seus attendance records em cascade)
- Se `mode = 'append'`: pular datas que já existem
- Criar meetings com `sequenceNumber`, `kind`, `details` preenchidos

**Entidades:** `Meeting`, `CatechesisClass`
